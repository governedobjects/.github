# Governed Objects

**An open specification for keeping a business's own records, meaning their identity, rules and
history, independent of the applications, vendors and AI systems that work with them.**

> No organization should have to depend on a particular software vendor, including us, to keep
> the identity, meaning, accepted state, relationships, governance and history of its own business.
> — [Project principles](https://github.com/governedobjects/governed-objects-spec/blob/main/PRINCIPLES.md)

Governed Objects is an early, experimental project. Everything here is open source under the
Apache License 2.0.

## Repositories

| Repository | What it is |
|---|---|
| [governed-objects-spec](https://github.com/governedobjects/governed-objects-spec) | The specification, its principles and its governance. **Start here.** |
| [governed-objects-conformance](https://github.com/governedobjects/governed-objects-conformance) | The open conformance suite. Anyone can test an implementation, without permission. |
| [governed-objects-python](https://github.com/governedobjects/governed-objects-python) | Python runtime. |
| [governed-objects-go](https://github.com/governedobjects/governed-objects-go) | Go runtime. |

## Get involved

- Questions and proposals: open an issue in the relevant repository. Changes to the specification
  follow its [governance](https://github.com/governedobjects/governed-objects-spec/blob/main/GOVERNANCE.md).
- Contributions are welcome under Apache 2.0, with a DCO sign-off (`git commit -s`). See each
  repository's `CONTRIBUTING.md`.
- Security issues: report privately to security@governedobjects.com, or through a repository's
  Security tab. Please do not use public issues.
- Everything else: hello@governedobjects.com.
